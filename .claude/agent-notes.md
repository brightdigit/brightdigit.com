- swift-format `[LineLength]` (limit 90) flags a long `Text("…")`/`Image(url:…)` call even when SwiftLint `line_length` is disabled via `// swiftlint:disable:next line_length`; those are separate linters. Fix by putting the long string/args on their OWN line inside the call: `Text(\n  // swiftlint:disable:next line_length\n  "…"\n)`. swift-format does not flag a bare string-literal-only line.
- #67 component-fidelity gotchas: (1) `Image(url:).class(x)` emits `src` BEFORE `class`, but the original `.img(.class,.src)` nodes usually put class first — use a raw `Node.img(.class,.src)` for any classed image. (2) `.attribute(named:).class()` DOES respect call order (match the original). (3) `Link(url:)` needs a `URLRepresentable` — pass `path.absoluteString` for a Publish `Path`. (4) A bare `<a>text</a>` (no href) needs a raw `Node.a`, not `Link(_,url:"")`. (5) Keep bespoke leaves (iframes with odd attrs, `.data(named:)`, `.raw(...)`) as raw nodes embedded in the component (Node: Component).
- Xcode/SwiftPM build (`swift build` via the Xcode toolchain) requires UNIQUE basenames across a whole target — two files named `PageHeader.swift` in different folders (`Components/About/` vs `Components/Contact/`) fail with `filename "X.swift" used twice`. When folder-organizing namespaced components, name files `Namespace+Type.swift` (e.g. `About+PageHeader.swift`) — they're `extension Namespace { struct Type }` anyway, so it's idiomatic and collision-free. `header.sh` auto-rewrites the header first line to match the current basename, so renames need no manual header edit.
- Deep component nesting can push string/`Text(...)` lines past swift-format's 90-col limit and trigger SwiftLint `multiline_function_chains` on `Type(multiline-args).convertToNode()`. Fix the chain by putting `.convertToNode()` on its OWN line after the closing `)` (both swift-format and SwiftLint accept this; swift-format won't reattach it). Trailing-closure calls like `Header { }.convertToNode()` are exempt from the rule.
- TailwindKit value tokens (#157): extensible `@theme`-scale families (Color, Spacing, Size, MaxWidth, TextSize, FontWeight, Radius, Shadow, DropShadow, Tracking, Ease) are modeled as SwiftUI-`Style`-shaped `protocol Foo: TailwindToken` + `public struct DefaultFoo` (INTERNAL init — public type is required for the `extension Foo where Self == DefaultFoo { static var … }` leading-dot trick, but it's not constructible by name). Fluent methods take `some Foo`; literal families (Spacing/Size) take concrete `DefaultSpacing`/`DefaultSize` so `.gap(4)` works. Fixed CSS-keyword families (Shade, Position, Flex, FlexDirection, ListStyle, Align, Justify, TextAlign, VerticalAlign, ObjectFit, BorderSide) stay CLOSED enums — "custom value" is meaningless. Shade is NOT extensible (v4 `blue-500` = one `--color-blue-500` var; custom = a new Color). Rationale + per-family v4-doc citations: `Packages/BrightDigit/TailwindKit/docs/tailwind-v4-value-model.md`. Removed `TailwindStyle+Custom.swift`; arbitrary values via each family's `.arbitrary(_:)` static, a custom conformer, or `TailwindStyle+Arbitrary.swift` (`.arbitrary(prefix:value:)`, `.arbitrary(prefix:variable:)`, `.custom(property:value:)`).
