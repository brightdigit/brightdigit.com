- Release-notes ordering (Leo, 2026-07-27): when squashing history for a release, write RELEASE_NOTES.md BETWEEN `git reset --soft <boundary>` and `git commit` so it is absorbed into the release commit itself — never a separate notes commit before or after. A commit named `v1.0.0-alpha.1` whose notes arrive in a later commit contradicts itself. Consequence: notes for every repo must be authored BEFORE the rewrite pass starts, and the post-squash sanity check is `git diff --stat <old-sha> HEAD` showing RELEASE_NOTES.md as the ONLY changed path (NOT an empty diff — the notes are a real content change).
