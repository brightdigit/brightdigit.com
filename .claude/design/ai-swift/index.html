How this maps to the build

Content in Markdown, skin in code

Nothing here is built yet. Once a direction and the copy are picked, this is the smallest implementation.

Content

Content/ai-consulting.md holds the offer, packages, app-teams track, FAQ, and CTA as front matter plus a Markdown body. The redesign re-skins the page and leaves this content untouched.

Routing

Add case "ai-consulting" to Pages.content(basedOnPage:). Unknown page paths throw missingContentFor today, so the Markdown file alone won't render.

Components

Add a page builder and a package-card component for Direction B. Testimonials reuse the Testimonial data the home page already uses.

Styling

Add one body#ai-consulting block to styles.css, built from the existing .button/btn and bellow-* tokens.

Links

Nav: add an explicit Link in HeaderComponent. Services: add a banner component above Services.Boxes.

Recommendation

Ship Direction B with these picks

  • Layout: Direction B, the pricing table. Buyers can compare the packages side by side, and the sections map straight onto front matter.
  • Offer: O1, "scattered AI experiments into tools, workflows, and a plan."
  • Packages: L1, which runs AI Readiness Audit → Team AI Setup → Ongoing AI Advisor. Apple-platform app teams get a separate track.
  • Pricing: Publish a price for the audit only (R1). The audit is bounded by Leo's time, so it can be priced confidently, and it turns interest into a real purchase. The later packages depend on what the audit finds, so they're quoted after it.
  • CTA: "Tell me about your team" (C1), which goes to the existing contact form. Add a booking link only after the page shows demand.
  • Slug and nav: /ai-consulting, with "AI Consulting" in the nav.
  • Proof: Three testimonials, labeled as general client work, because none of them is about AI. Episode 208 carries the general AI angle and episode 210 carries the app-team angle.
