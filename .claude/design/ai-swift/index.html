How this maps to the build

Content in Markdown, skin in code

Nothing here is built yet. Once a direction and the copy are picked, this is the smallest implementation.

Content

Content/ai-swift.md holds the offer, packages, FAQ and CTA as front matter plus a Markdown body. The redesign re-skins it and leaves the content alone.

Routing

Add case "ai-swift" to Pages.content(basedOnPage:). Unknown page paths throw missingContentFor today, so the Markdown file alone won't render.

Components

An AISwiftBuilder page builder, plus a package-card component (Direction B). Testimonials reuse the Testimonial data the home page already uses.

Styling

One body#ai-swift block in styles.css, built from the existing .button/btn and bellow-* tokens.

Links

Nav: an explicit Link in HeaderComponent. Services: a banner component above Services.Boxes.

Recommendation

Ship Direction B with these picks

  • Layout: Direction B, the pricing table. Productized packages need to be compared, and B's sections map straight onto front matter, which keeps the redesign rework near zero.
  • Offer: the outcome-led sentence (O1).
  • Packages: Audit → Pilot → Team enablement (L1). Each package is a natural upsell into the next, and the audit is a low-risk first purchase.
  • CTA: the existing contact form with "Tell me about your app" (C1). Add a booking link only after the page shows demand.
  • Slug and nav: /ai-swift, with the nav label "AI + Swift".
  • Proof: the three testimonials below, labeled as general client work, since none of them is about AI. Pair them with episodes 208 and 210, which are about AI directly.
